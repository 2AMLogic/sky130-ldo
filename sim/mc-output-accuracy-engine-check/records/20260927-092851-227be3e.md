The PDK does NOT -- and that took a harness fix to be true rather than merely hoped for. `klt sim`'s request names `models.lib` by a relative path, so before issue #211 `klt` resolved the PDK root itself and, on this host, picked a DIFFERENT sky130A install from the one sim/pdk.json pins and `mc-run.py` verified (a build whose `libs.tech/combined/continuous/models_fet.spice` -- the FET cards the mismatch draws come from -- is not byte-identical to the pinned root's), while the record still said `matches_pin: true`. `mc-run.py` now passes `PDK_ROOT` explicitly and asserts, after the run, that `klt`'s own `provenance.pdk.version` names the pinned open_pdks commit, so this campaign and the campaign of record read the same model build by construction and the remaining difference really is the executor. A negative control compares the control's sample set against the nominal's, so an executor difference between the two sits underneath the comparison as a confound. Two things about that confound are open questions this campaign's per-sample values answer, rather than assertions it starts from: whether the seed contract removes it (i.e. whether the same seed on a byte-identical deck reproduces the same per-instance AGAUSS draws across engine versions, making the two sample sets a paired series rather than independent draws), and how large the executor's contribution to the vout_ss DISTRIBUTION is next to the mean shift the seeded defect deliberately introduces. This campaign therefore runs the nominal bench UNCHANGED -- same testbench schematic (referenced, not copied), no `netlist_patch`, so its netlisted deck is byte-identical to the campaign of record's committed snapshot (sha256 e760a7c355bf0959db8333130b8bb5253a7bfad0e63d07b68ccf6dbfa2ca9b47) -- at the same mismatch point, with the same seed, on the same host and ngspice build that produce the negative control's samples. Comparing its vout_ss distribution against the campaign of record's is what turns 'the executor difference is small relative to the seeded defect' from an assertion into a measurement (this repo's CLAUDE.md: no claim without a testbench). What it is not: it is not a supersede of, or a competitor to, the campaign of record -- it carries a deliberately smaller N chosen for the cross-check, and `sim/mc-output-accuracy` remains this block's statistical campaign of record.
