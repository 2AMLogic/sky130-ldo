As of #179 both points are seeded per sim/README.md's initial-condition contract (#171): the testbench carries a .nodeset card seeding the three branch-defining nodes (VOUT=1.8, FB=1.2, N_FBB=0.6), which ngspice applies to EVERY operating-point solve in the deck -- including the one each `ac` performs for itself -- so neither the 1mA point nor the `alter`-reached 50mA point linearizes around an unconstrained Newton solve. `.ic` would not have done this: ngspice honours `.ic` only for the transient operating point, so it is inert in an ac-only deck. Only the branch-defining nodes are seeded: a .nodeset card is a single static card applied to both load points, and the eleven-node seed from sim/ic-screen-125c-b (its 125C/50mA values) was measured to drag ss/-40C/3.63V's 1mA point onto a non-regulating branch (VOUT=3.633V=VIN), reporting 0.017dB of PSRR there instead of 25.7dB -- see sim/README.md's "#179".
