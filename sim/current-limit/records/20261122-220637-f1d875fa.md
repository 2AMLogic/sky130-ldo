- **Claim**: Substantiates spec/target-spec.md's ratified "Current limit" row (constant-current (brickwall) clamp, window TBD over PVT; never engages for I_load <= 50 mA; survives continuous Vout = 0 short at Vin_max) against the sense-FET current comparator and gate clamp issue #22 added to design/ldo_3v3in_1v8out.sch (M_SENSE / M_CLN1 / M_CLN2 / M_CLP / M_CLIM -- see design/README.md's "Current limit (#22)"). The row is ratified by issue #1 / DR-006 and it deliberately carries NO numeric clamp window: the window is "TBD over PVT". This experiment therefore splits the row rather than blurring it -- the clauses that carry a number are bounded below ("never engages for I_load <= 50 mA" becomes ilim_short_ma/ilim_knee_ma > 50 mA plus vout_50ma_v inside the ratified Output row's 1.764-1.836 V window), and the clause that does not ("window TBD over PVT", "survives") is measured and reported WITHOUT a bound, because establishing that window over PVT is exactly what the row asks for at this stage; inventing a ceiling would be the invented settled number CLAUDE.md forbids. "At Vin_max" is covered by the corner runner's own supply axis (the 3.63 V column), not by a hard-coded VIN. Legs 1 and 3 are both `tran ... uic` with EN rising at t=100us, so each reaches regulation through a real soft-start ramp from a cold start rather than from an ngspice operating-point solve of the fully-enabled loop: the initial-condition contract's first accepted shape (uic + an EN edge -- sim/README.md, issue #171). Issue #76 gave leg 3 its EN edge after PR #75 shipped the same fix in sim/startup and sim/enable-shutdown (the ff/sf 125C nuisance-trip mechanism of issue #69); issue #177 then replaced leg 1's bare unseeded `op` with the same transient AND added the `uic` keyword to both legs, because the EN edge alone does not remove the hazard: ngspice solves a transient operating point before a non-uic tran, and for a source carrying both a dc value and a transient function that solve uses the DC value ('vsup', fully enabled -- ngspice prints "Note: ven: dc value used for op instead of transient time=0 value" on stderr every run), which #177 measured tripping `Warning: Dynamic gmin stepping failed` on BOTH transient legs. `uic` skips that solve; measurements are unchanged by it. Leg 2's `dc` sweep is the one analysis that still solves with EN at its dc value, and that is not the forbidden shape: the forcing branch (RFORCE = 1 mOhm) pins VOUT at every swept point, so there is no free regulating branch for the solver to pick, and each point after the first continues from the previous point's converged solution. #177 measured it emitting no solver-diagnostic marker at the three quick corners (its gmin stepping completes rather than failing); the 45-corner fleet re-run (record 20261117-173516-d843d914) then found that claim too narrow -- 4 of 45 corners, all on the 3.63 V Vin_max column, tripped the #171 gate in the sweep's first continuation steps at the dead-short end (singular matrix on xldo.ea_cz / xldo.n_fbb, or Dynamic gmin stepping failed), with every measured value still inside its bounds. Issue #647 therefore seeds the sweep with the testbench's IC_SEED `.nodeset` card -- the contract's seed shape for a `dc` analysis (#178/#189, the thermal precedent), values measured from the settled held-short end state of leg 3's own transient at tt/27C/3.30V, the sweep's own starting point -- and runs the leg FIRST in the deck, the configuration every seeded bench in sim/ uses; the four failing corners and the matrix extremes then solve with zero diagnostics and graded values unchanged to 4-5 significant digits. The short is applied as an event at t=1.0ms -- after sim/startup's measured 0.26-0.45ms soft-start ramp completes -- and HELD to t=3.0ms: 2 ms of continuous Vout = 0, a defined duration rather than a single sampled instant, since "survives" is a claim about holding the fault.
