# Pinned klayout-tools (`klt`) install for layout/'s DRC/LVS flow (issue #2).
#
# klt's PyPI release lags `main` by several verbs -- `extract`, `lvs`, and
# `gen` (all required by this flow) are documented but not yet released
# there as of this pin (see https://github.com/2AMLogic/klayout-tools/issues/342,
# already tracked upstream). The project's own README names installing from a
# git ref as the sanctioned way to get the latest development verbs:
#
#   uv tool install git+https://github.com/2AMLogic/klayout-tools
#
# This pins an exact commit rather than floating `main`, for the same
# reproducibility discipline sim/pdk.json applies to the PDK version: a
# re-run months from now installs the identical `klt` build instead of
# whatever `main` has drifted to. Bump this pin deliberately (and re-run
# layout/bin/run-trivial-cell-flow.sh to refresh the checked-in report) when
# picking up new `klt` capability.
#
# Same commit as the sibling sky130-bandgap repo's own layout/requirements.txt
# pin, chosen deliberately: that repo proved this exact trivial-cell DRC/LVS
# flow (gen mos_array -> drc -> extract -> lvs) against this same sky130 PDK
# pin already, so reusing its `klt` commit gives this repo's first layout
# flow run a known-good starting point instead of an unverified new pin.
klayout-tools @ git+https://github.com/2AMLogic/klayout-tools@acb0ae6c11e667eb93ee7de272d64298517f7fab
